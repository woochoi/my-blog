인터넷까지

빈 폴더가 블로그 주소가 되기까지, 단계별로 다시 따라가 보기

02
📍

0단계 · 출발점

둘은 아직
서로를 모른다

내 컴퓨터git init만 된 빈 폴더
커밋 0개 · master
GitHubREADME.md 하나
Initial commit · main

작업 전엔 항상 git status로 상태부터 확인!

03

1단계 · 연결하기

origin이라는 이름으로
GitHub를 등록

  • git remote add origin <URL>
  • git remote -v등록 확인
  • git ls-remote origin접속 확인

origin은 원격 저장소의 별명. 관례적으로 이 이름을 쓴다.

04

2단계 · 기록 맞추기

원격의 기록 위에서
시작하기

  • git fetch origin기록 받아오기
  • git checkout -b main --track origin/main
  • git branch -D master빈 브랜치 정리

--track 덕분에 이제 push / pull 하면 origin/main과 주고받는다.

05
🧱

3단계 · 블로그 만들기

HTML · CSS · JS
세 가지면 충분

index.html 글 목록 · style.css 디자인 · posts/ 글 파일

카드 넘기기는 CSS scroll-snap과 짧은 JavaScript로.

06
🔍

4단계 · 로컬에서 미리보기

올리기 전에
내 컴퓨터에서 먼저

python3 -m http.server

미리보기에서 찾은 버그 두 개를 배포 전에 고쳤다. 카드가 너무 커서 버튼이 밀리는 문제, 연속 키 입력 문제.

07
🚫

5단계 · 첫 push는 실패

"너 누구야?"
GitHub의 질문

add→ commit→ push ❌

could not read Username. 커밋은 로컬에 잘 남았지만, 이 컴퓨터엔 GitHub 로그인이 없었다.

08

6단계 · 로그인

gh auth login

  • GitHub.com어디서 쓰나요?
  • Web browser어떻게 로그인?
  • HTTPS통신 방식
  • Yes ⭐git도 이 로그인 사용

일회용 코드를 브라우저에 입력하면 "you're all set!"

09
🌐

7단계 · push 성공, Pages 켜기

저장소를
웹사이트로

364a43f..90b35cd main → main 드디어 GitHub에 올라갔다.

Settings → Pages → Branch: main / root → Save

✅

building · 404→ built · 200
